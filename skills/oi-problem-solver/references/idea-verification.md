# 用户思路的独立重建与验证

## 先重建，后评价

先用自己的语言给出：

- 状态／对象表示什么；
- 每个操作、转移、选择或查询做什么；
- 初态、终态和答案如何取得；
- 用户依赖的关键性质；
- 性质的前提与依赖；
- 算法必须保持的不变量。

请用户确认只限于重建仍有多种实质解释时。不能只凭“这是 CDQ／贪心／线段树”套模板，也不能因存在常见正解而替换原思路。

## 命题图

将完整算法拆为可核验节点：规格映射、引理、转移合法性、覆盖性／最优性、终止、答案提取、复杂度和实现不变量。边表示“当前命题依赖哪些前提”。按拓扑序处理；首个未成立节点会阻塞后续证明。

对每个关键节点同时执行两条路线：

1. **尝试证明**：选择适合的方法，写出缺一不可的步骤。
2. **尝试证伪**：枚举最小规模、重复／平局、极值、空对象、退化图树、不同操作顺序及用户省略的前提。

找到证明缺口不等于最终命题为假。若能精确指出首个无效推理边，可将“该推理步骤成立”标为 `REFUTED`，同时让尚未被反例否定的最终命题保持 `UNRESOLVED`；合法反例或反证才可直接 `REFUTED` 最终命题。找不到反例也不等于 `PROVED`。

## 正确性两方向

- 转移／构造：证明产生的每个候选都合法（可靠性），任意合法／最优解都被覆盖（完备性）。
- 等价／充要：`A⇒B` 与 `B⇒A` 分开，检查每次变形可逆性。
- 最优化：分别证明可行性和不劣／最优；局部合法不是贪心安全性。
- 数据结构：证明抽象操作与物理状态一致，逐个原子更新保持不变量。
- 非标准方案：若以上义务关闭，即使与题解不同也应保留，并说明它成立的真正原因。

## 反例优先级

先试能隔离单个性质的小例：最小 `n/m`、最少操作、最少不同值、最小数值。对严格／非严格关系优先试相等；对懒标记试不同操作顺序；对持久化试分叉版本后重读旧根；对图算法试重边、自环、不连通、负边；对 DP 试两个历史状态值相同但未来不同。

程序穷举前独立定义 oracle，避免待审算法与暴力共享同一错误观察。缩小后重新验证合法性、正确答案和真实算法轨迹。

## 状态语义

- `PROVED`：全体允许输入的关键证明义务已关闭。
- `REFUTED`：给出合法输入、独立期望与实际矛盾，或对精确命名的推理步骤给出首个无效逻辑边；不得借步骤失败宣称最终命题必假。
- `CONDITIONAL`：列出使证明成立的全部附加条件，并说明原题是否给出。
- `TESTED_ONLY`：记录域、次数、种子和未覆盖范围。
- `UNRESOLVED`：指出具体阻塞节点和所需材料／引理。
