# 优化、最小修改与码风继承

## 优化前置条件

先判断原算法是否正确；若错误，区分“修复后再优化”和“瓶颈本身来自错误逻辑”。从实际循环、操作次数、分配和峰值内存定位瓶颈，不能只凭算法名称。

## 优先顺序

1. 去除重复计算、复用中间值；
2. 合并转移、前后缀／滑窗／单调性；
3. 改善数据结构维护；
4. 内存布局、预分配、迭代替递归等实现优化；
5. 常数与 I/O；
6. 仅当原路线无法满足约束时才提替代算法。

前后缀“排除一个孩子”需关联运算与单位元；单调队列需证明候选淘汰安全；缓存需计生命周期和失效；reserve 计 capacity 而非元素数。

## 修改范围与风格

严格保持变量／函数名、缩进、空格、括号、宏、类型别名、全局数组、STL 习惯、I/O 和文件组织。优先：局部表达式 → 函数 → 必要结构 → 局部重构 → 整体重构 → 换算法。

不得为了“现代化”擅自：把数组换 vector、删除 `#define int long long`、改名、引入类／模板、格式化全文件、改变算法或输入输出。若这些本身是阻塞根因，说明证据并请求扩大授权。

用户只允许某函数时：可以阅读调用者以理解契约，但补丁只能触及该函数；若无法局部修复，返回阻塞点，不越界修改。

## 收益说明

每个优化标注层次（逻辑／算法／结构／实现／常数）、原成本、优化后成本、额外前提、内存变化、实现风险。树形 DP 从每个孩子重算其余孩子到前后缀时，应按 `Σdeg² → Σdeg` 推导，并检查星形树最坏情况。

替代算法须比较原限制、依据、复杂度、实现难度、适用条件及可保留的原观察；不能只给新算法而不回答原瓶颈。

## 可复用 C++ 补丁指标

在行为验证之外运行 `oisolver style --before ... --after ...`：

- token Levenshtein 距离与归一化距离；
- 轻量结构 token-tree 距离，以及可选 clang JSON AST 距离（clang 不可用时明确记 unavailable）；
- changed lines、授权 `OLD=NEW` 替换之外的 nonessential changed lines；
- 原标识符、宏、每个缩进前缀和空行的保留率；
- 快 I/O 与全局数组是否保留。

指标对无必要改名、宏删除、全局数组→vector、快 I/O 删除、重排缩进／空行和大范围改写发出警告并扣分。它是可审计的保守启发式，不判断语义等价；低编辑距离不能替代正确性，高距离也可在已授权重构中合法。CLI gate 默认要求 nonessential line rate 不超过阈值，授权替换必须显式列出。

V3 的 `oisolver style-calibrate --corpus tests/fixtures/style-calibration/corpus.json` 在 12 个标注修复上扫描阈值。样本覆盖紧凑／展开格式、`#define int long long`、全局数组／vector、iostream/scanf/getchar 快读和位运算写法；0.10 是该 corpus 上最严格的零误拒／零漏拒值。新阈值必须提供逐样本 warning、false-positive/false-negative 表，不能为了让当前补丁通过而临时放宽。可选 clang AST 只有真实 probe 成功才记 available；clang 缺失记 degraded，不把轻量 token tree 冒充 compiler AST。

## 验证

先锁定原行为和反例／基准，再应用最小 diff；运行正确性回归和必要性能测量。实测只报告环境和输入，不能用一台机器的毫秒数替代理论界。交付说明是否改变算法与复杂度。
