# C++ 代码审查

## 先还原程序模型

在找错前说明：变量与理论量的映射、函数职责、核心结构、初始化、状态更新、查询、答案提取和维护不变量。沿真实数据流读，不因代码像某模板就认为实现了模板。

## 三层核验

### 1. 算法层

状态是否足够、转移是否可靠且完整、贪心是否安全、数据结构接口是否支持需要的操作、答案是否对应目标。题意中的重复／平局／空对象／多测是否都进入模型。

### 2. 理论—实现一致性

逐项把证明中的初态、更新顺序、端点、单位元、旧／新值、终止和答案映到代码行。特别检查：

- 0/1 背包滚动方向、DP 不可达值；
- 懒标记 `apply` 与 `compose(new,old)` 的函数顺序，push/pull 时机；
- 持久化写操作是否只触及新节点，query 是否意外 push；
- CDQ 平局分组、撤销范围、排序状态；
- 多测清空和全局计数器／内存池复位。

### 3. C++ 语义与资源

- 数组／节点池末端、`r+1`、负下标、空 vector 的 `size()-1`；
- 有符号溢出、乘法先溢出再赋给 `long long`、差值先在 `int` 求值、INF 运算；
- signed/unsigned 转换、负／超宽移位、位运算优先级；
- `#define int long long` 对 main、库接口、内存和重载的影响；`__int128` 的工具链与输出；
- 未初始化、除零、失效迭代器／引用、跨 `vector::push_back` 保存引用；
- 宏副作用、自定义快读的 EOF/负号、混用 stdio/iostream；
- 递归最坏深度、栈帧、容器 capacity、静态池上界；
- 多测状态、异常出口和 I/O 协议。

## 执行边界

默认先静态核验。用户授权且环境合适时编译运行；记录编译器版本、标准、优化／警告／Sanitizer 参数、输入和预期。编译成功不是正确性证据；Sanitizer 只覆盖实际路径。执行不可信代码需要外部沙箱，OISolver 的超时不是内存／文件系统安全边界。

## 发现格式

每项给：`分类 / 代码位置 / 触发条件 / 理论预期 / 实际轨迹或语言语义 / 确定程度 / 最小修复方向`。区分算法错误、实现不符、C++ UB／转换、资源超限和仅可读性建议。同一根因去重，多个独立错误按实际触发顺序处理。
