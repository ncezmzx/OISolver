# 动态工作流路由

先判断输入材料和用户真正请求；多个流程可组合，但不机械执行无价值步骤。

| 输入／请求 | 必做 | 不应默认做 |
|---|---|---|
| 只有完整题面 | 形式化目标与范围，按要求研究算法 | 未要求时不直接输出长篇完整题解 |
| 不完整口述题面 | 列事实、解释分支及改变算法的未知项 | 不为熟悉算法擅补约束 |
| 只有思路／猜想 | 独立重建，提关键命题，证明与证伪 | 不因算法名相似就判对错 |
| 思路 + 官方题解 | 分开审查两条推导，再比较关系 | 不把“官方”当作免检证据 |
| 思路 + 代码 | 分别判断理论、实现一致性与实际成本 | 不以理论正确替代码 PASS |
| 只有 WA／RE 代码 | 建模、找小诊断例、首个偏离、最小修复、回归 | 默认不先公布整套答案和错误行 |
| TLE／MLE | 从实际循环、操作数、节点数与峰值内存核算 | 不凭算法标签猜瓶颈 |
| 已 AC 代码 | 只审用户指定的正确性、资源或表达范围 | 不把 AC 当无 UB／全环境正确 |
| 优化要求 | 先确认正确性与瓶颈，保留原思路做最小优化 | 不把标准解当唯一回答 |
| 局部结论 | 明确命题、前提、方向、证明和边界 | 不套完整题解模板 |
| 完整题解 | 从约束推导观察、算法、证明、成本、实现与边界 | 不只介绍模板流程 |
| 对拍要求 | 独立暴力、合法生成、固定种子、保存失败、合法缩小 | 不把未执行脚本写成通过 |
| 只改某函数 | 审查必要上下文，补丁严格限于函数，说明外部阻塞 | 不顺手重命名／格式化其他代码 |

## 何时询问

只有未知项会实质改变答案且无法从现有材料确定时询问。能条件化回答时，先分别给各解释的结论。典型必须澄清项：重复是否允许、空集定义、图的方向／连通、总规模约束、多测总和、取模、交互协议、修改范围、用户是否希望渐进提示。

## 任务终止条件

- 已得到满足请求的严格结论与必要证据；或
- 找到首个合法反例／实现偏离并完成用户要求的修复层次；或
- 关键规格／依赖缺失，已列出最小补充材料；或
- 测试预算耗尽，结论准确停留在 `TESTED_ONLY`／`UNRESOLVED`。

不要为“看起来完整”继续无目标检索、随机测试或重写。
