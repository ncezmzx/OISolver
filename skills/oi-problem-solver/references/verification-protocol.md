# 四层验证与结论关闭协议

所有技术任务先判断四层中哪些适用；适用层未完成必须就地说明，不能由另一层替代。

## Layer 1：理论验证

固定题意、量词和规模；提取命题、必要／充分方向、不变量和依赖；证明算法合法性、覆盖／最优性、终止与实际复杂度。输出证明链及仍未关闭的前提。

## Layer 2：反例验证

主动挑战每个关键命题：最小规模、相等／重复、空对象、极值、退化图树、操作换序、多测与缺失前提。反例须同时给合法性、独立真值和待审方法轨迹。证明某一步无效但尚未否定最终命题时，精确把 `REFUTED` 施加于“该推理步骤”，最终命题保持 `UNRESOLVED`，禁止偷换对象。

## Layer 3：程序验证

在授权和隔离环境编译／运行；独立 oracle、合法生成器、固定种子、次数、命令、编译器与参数齐全。oracle 失败是基础设施错误。有限范围无差异只支持 `TESTED_ONLY`；若枚举域被证明等于完整输入域，才可把“穷举覆盖”作为相应有限命题的证明材料。

## Layer 4：实现审查

把理论状态／不变量映射到变量、端点、更新顺序和答案；检查 C++ 求值类型、UB、溢出、越界、生命周期、多测、栈、节点池、容器 capacity、I/O 和实际常数。算法证明不关闭这一层，AC 也不关闭跨环境的 UB／资源问题。

## 关闭矩阵

| 证据 | 能支持 | 不能单独支持 |
|---|---|---|
| 完整证明 | 抽象算法在明确前提下 `PROVED` | 代码忠实、无 UB、实际资源可过 |
| 合法反例 | 被精确定义命题／步骤 `REFUTED` | 其他维度失败、替代算法正确 |
| 随机／有限对拍无差异 | 记录范围 `TESTED_ONLY` | 全称正确性 |
| 编译／样例／Sanitizer 通过 | 实际路径上的有限证据 | 未走路径、理论正确性 |
| AC | 该评测与环境下被接受 | 证明严谨、无未触发 UB、其他约束版本 |
| Catalog 命中 | 身份、来源和检索线索 | 当前变体的前提、证明或实现正确 |

## 五态使用

- `PROVED`：Layer 1 对该命题完整关闭；若结论声称“程序正确”，还须 Layer 4 关闭。程序验证可补强但不是必要替代。
- `REFUTED`：合法反例、严格反证，或对精确推理边给出首个无效步骤。必须说明被否定的是命题、证明还是实现。
- `CONDITIONAL`：列全附加前提并说明原题／代码是否满足。
- `TESTED_ONLY`：Layer 3 有实际记录，理论仍未关闭。
- `UNRESOLVED`：指出阻塞层、缺失材料和下一项最小检查。

交付前复查：是否把测试写成证明、把证明写成代码 PASS、把实现反例写成算法反例、把不存在的执行记录写成已运行。
