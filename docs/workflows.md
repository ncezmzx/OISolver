# 核心工作流

## 1. 从题面到算法

固定事实与未知 → 形式化输入／输出／约束 → 分析朴素法与瓶颈 → 提取观察 → 对每个观察证明与证伪 → 得到算法 → 正确性证明 → 实际复杂度与可行性 → 实现细节与边界。

## 2. 用户思路

先准确复述状态、操作、目标和依赖。建立命题图，逐节点给五态。正确的非标准方案保留；错误时指出首个失败节点、合法反例和能否局部修补，再可选比较标准方案。

## 3. WA Debug

程序模型 → 小诊断例 → 正确答案 → 程序关键轨迹 → 首个偏离 → 不变量根因 → 最小 diff → 原例和边界回归 → 必要时固定种子对拍。用户要求直给时从根因／补丁开始，但不省略证据。

## 4. TLE / MLE

从真实实现按阶段、层、操作和生命周期记账；找最坏形态；结合限制判断。先做重复计算、前后缀／缓存、维护方式和内存布局，再考虑换算法。每项优化说明前后界、额外条件和验证。

## 5. 差分测试

独立定义 brute → 证明小域正确 → 合法生成器／validator → 固定 seed → candidate/oracle 同协议 → 保存首差异 → validator 守卫缩小 → 修复 → 原反例回归和新种子。oracle 失败是基础设施错误。

## 6. Catalog

按模型检索 CPscore ID → 消歧 → 记录 hash/revision → 读取适用条件线索 → 独立证明当前题目。只有跨题复用、去重且证据充分的声明才加入外键扩展；临时猜想留在会话。

## 7. 与 OIBlogScore

把已验证的求解结论导出为中立 evidence → OIBlogScore 绑定文章原文和版本 → 独立选择六态 verdict、覆盖率和修复政策。求解代码的授权修改不转化为博客修改授权。

## 8. V3 渐进修复链

不完整题面按四类台账保留未知 → `repair init` 创建 fail-closed scaffold → Agent 依次填写模型、诊断输入、正确答案、轨迹、首偏离、不变量／根因、最小修复、回归 → 独立 oracle + 合法生成器 + validator → `repair run` 自动执行 compiler/sanitizer probe → 原程序诊断与 difftest/shrink → 最小 style gate → patched sanitizer → 相同 seed 回归。任一机械层失败就停在对应状态；即使全链完成，全范围算法正确性也不从有限测试升级，仍需独立证明。
